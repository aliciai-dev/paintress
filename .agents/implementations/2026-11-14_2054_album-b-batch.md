# 2026-11-14T20:54+08:00 — 画谱 B1–B6：token 分类、谱式、审计、提取、调整、面板

规格：`specs/album.md`。框架子集（预设面板 / 组件画廊）已在 0.6.0 落地，
这一批补的是**三层里的引用链与三个操作**——没有它们，画谱只是「一堆变量」。

## 改动

### B1 token 分类

- `PresetType` 从 `color | radius` 扩到 `color | radius | spacing | font`；
  落盘类型跟随（color→color，radius/spacing→number，font→string）。
- `paintress_preset` 的 `type` 枚举、CLI 用法同步；预设面板按 kind 分组
  （颜色色块 + 十六进制、数值 number、字体文本）。

### B2 谱式：preset 组 + 节点引用

- 存储：`x-paintress.presets.groups.<name> = { target, props }`，`props` 的值是 `$token`。
- 节点加可选字段 `preset: '<name>'`；渲染前 `applyPresetRefs()` 把组属性铺在节点自身属性**下面**
  （显式属性优先），保存永远写原文档——不烤值。
- 写 token 与写组共用一次 `writePresets()`，两边都不会再把对方抹掉（之前 setPreset 会整块重写 presets）。
- 校验：悬空 preset、target 与节点类型不符、组里写裸值 → 三类警告；`validate` 工具与写前门禁都带上了组。
- 写入入口并入 `paintress_preset`（`set-group` / `remove-group`），不另起工具。

### B3 audit（只读）

`paintress_audit` / `paintress audit`：
越界裸值（可替换成 token，且给 `$key` 建议）、孤儿 token、未被引用的 preset 组、
悬空/类型不符的 preset 引用、组里的字面量。`metadata.allowLiteral` 的子树跳过裸值检查。
输出结构化 `findings` + `counts` + 一句 `summary`。

### B4 establish（提取）

`paintress_establish` / `paintress establish`：
同一字面量（颜色/圆角/间距）出现 ≥ `minUses`（默认 2）次 → 建议 token，
key 由值推导（`color-3b82f6` / `radius-8`），可重复运行不产生重复 token；
同类型节点带同一组属性 ≥ 2 次 → 建议 preset 组（属性全部映射到 token 才建组）。
`apply=false` 只给建议，一个字节都不写；`apply=true` 写预设文件并把命中节点改写成
`$token` / `preset: <组>`，一次 mtime 保护的保存。

### B5 adjust（改一处，全项目跟着变）

`paintress_adjust` / `paintress adjust`：
`key` 改 token，`group + prop` 改组属性；默认 dry-run，返回受影响节点与 `before → after`
（token 的影响面包括引用它的 preset 组）。`apply=true` 只写 `__preset.ptr`——
设计稿里是引用，所以整个项目同时变，不需要批量改稿。

### B6 面板

预设面板按 kind 分组编辑 token；preset 组以只读卡片展示（组名 + target + 属性 → `$token`）。
「改一处看全局」的手感落在画布上（SSE 触发重渲染），面板不新增写路径。
