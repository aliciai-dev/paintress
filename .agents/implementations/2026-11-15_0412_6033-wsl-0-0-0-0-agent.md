# 2026-11-15T04:12+08:00 — 查看器端口阶梯：默认 6033，WSL 宿主访问不到时自动换端口/改绑 0.0.0.0，并把可用地址报给 agent

现场：`paintress web` 起得来、WSL 内 `curl 127.0.0.1:3316` 返回 200，但宿主（Windows）Firefox 报「连接失败」。

实测根因链：
- Windows 侧 `Get-NetTCPConnection -LocalPort 3316` 为空，而 17318 / 34179 / 80 都有 `wslrelay.exe` 监听 → 转发机制本身没坏；
- Windows 侧 bind `127.0.0.1:3316` 失败（WSAEACCES 10013），对照 `127.0.0.1:4316` 成功；
- `netsh int ipv4 show excludedportrange protocol=tcp` → Hyper-V 保留了 `3228–3327`，3316 正在其中；
- 该机器动态端口段曾被改成 `1024–15000`，Hyper-V 每次开机在这段里重划保留块，位置会漂（所以「重启过」也没用）。

即：WSL2 的 `localhost` 转发由宿主侧 `wslrelay.exe` 落地，Windows 上绑不上这个端口，转发就不存在；发行版内部永远自测通过，这类故障在 WSL 内不可观测。

## 做了什么

1. **默认端口 3316 → 6033**（`src/web/bind.ts`），`ui/vite.config.ts`、两份 README、SKILL 同步。
2. **新模块 `src/web/bind.ts`**：先定端口、再起服务、最后复核。
   - 阶段 0 宿主体检：一次 PowerShell 调用同时取回 Hyper-V 保留段 + 三个候选端口的独占可绑性（`ExclusiveAddressUse`）；
   - 阶段 1 选端口：按 `127.0.0.1 × [6033,6133,6233] → 0.0.0.0 × [6033,6133,6233]` 逐个试绑后立刻关闭；
   - 阶段 2 用确认过的端点真正 listen（只绑一次，不再「起了再拆」）；
   - 阶段 3 端到端复核：宿主侧 `GET /api/ping?nonce=…`，正文必须回显本次进程随机 nonce（不认 200，避免「端口上蹲着别的程序/另一个 distro 的 paintress」被误判）。
   - 整条阶梯硬上限 9s；`ensureDaemon` 等待上限 6s → 15s。
   - 显式 `--port` 只产生一个候选、不跳级（被占直接报错）；`port: 0` 整段跳过。
   - 新增 `--bind auto|loopback|all`。
3. **`src/shared/wsl.ts`**：把 `isWsl()` 从 `open-browser.ts` 迁出并被两处复用（浏览器落点 + 端口策略），另加 `windowsSystem32()` / `interopEnabled()` / `defaultRouteIpv4()`。
4. **agent 可见性**：`pong` 增加 `access{url,host,bind,windows,jumped,requestedPort,attempts}`，一路带到 `ensureDaemon` → `ViewerInfo` → `paintress_viewer`（含 `note`）/ `paintress web` / `paintress status` / daemon 页面；旧版 daemon 不回该字段时按本机 loopback 兜底。CLI 的 `http` 字段保持历史形态（无结尾斜杠），值取 `access.url`。
5. **`paintress doctor` 增加 `net` 一节**：WSL 判定、interop、系统盘、默认路由 IP、三个候选的保留段/可绑性、运行中 daemon 的实况。
6. 顺手修掉一个既有缺陷：`startDaemon` 绑定或 socket 失败时不释放单实例锁（会让下一次启动被「已在运行」挡住）。
