# 2026-11-15T04:26+08:00 — 审查修正：后台启动保留端口错误明细，并发启动正确复用胜者

本轮为第三方审查后的修正，范围限于端口阶梯与查看器启动链路。

确认并修复：
- `ensureDaemon` 原先把后台子进程 stderr 全部丢弃，导致显式端口冲突和六候选全灭只剩通用退出码；改为有界捕获并随错误返回，成功后继续 drain 且 unref 管道，后台 CLI 不会被常驻进程拖住。
- 宿主体检拉长了单实例锁到控制面 socket 就绪之间的窗口；并发启动的输家原先提前报错。现在识别锁竞争并继续轮询胜者，`started` 按胜者 pid 是否等于本次子进程计算，避免重复弹窗。
- `reuseDaemon` / `paintress web` 原先静默忽略与现有实例不同的 `--bind`；现在与端口一样明确冲突报错，并补测试。
- WSL 的 all 模式若没有可用网卡 IPv4，不再返回 `http://0.0.0.0:...` 假成功；该候选记为不可达。
- 删除会抢先截断 0.0.0.0 兜底的全局 9s 阶梯上限，改为单次 Windows 调用服从每个候选的剩余探测预算。
- 精简视图显示实际监听端口和绑定地址，不再在跳级后显示请求端口。
- `open-browser.ts` 真正复用 `shared/wsl.ts` 的 `isWsl`，保留原 re-export，删除第二份判据。
- 为解除检查阻塞，`test/web.spec.ts` 中既有的局部变量 `escape` 重命名为 `traversal`；无行为变化。

证据：`pnpm check`、`pnpm test`（417 passed）、`pnpm build` 全绿。真机复测：后台显式端口占用返回完整错误；六候选全灭返回六行明细；双进程同时启动两端退出 0、同一 pid，一端 `reused=false`、另一端 `reused=true`；运行中的 loopback 实例拒绝 `--bind all`；占用 6033 后查看器跳到 6133，精简页显示 `端口 6133 · 绑定 127.0.0.1`。
